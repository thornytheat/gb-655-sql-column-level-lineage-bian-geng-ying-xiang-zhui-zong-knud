# 定义 lineageguard

本文件是字段含义与计算方式的唯一出处；页面只显示字段名、状态与数值。

## 1 字段身份

- `field_id`：字段身份，字符串，跨版本不变。改名不产生新身份。
- 无 `field_id` 时按 `sha256(表名|列名)` 取前 12 位派生，前缀 `auto:`，与行序无关。
- 同一身份在一个版本里出现两次：第二次进隔离区，原因码 `FIELD_ID_DUP`。
- 同表列名比较不分大小写；保留首次出现的列，重复列进隔离区。
- 身份是 2^53 以上的整数时一律按字符串保存与导出，禁止过 `float`。

## 2 类型格

一个类型归一成 `{族, 基础类型, 精度, 标度, 长度}`，族为 numeric / text / temporal / bool / unknown。

每个数值类型带四个 Decimal 常量：

| 常量 | 含义 |
|---|---|
| `lo` / `hi` | 可表示的取值范围 |
| `quantum` | 最小刻度，例如 decimal(18,2) 为 0.01 |
| `exact` | 能不丢精度表示的最大整数绝对值，double 为 2^53 |

从旧类型到新类型判为放宽（`widen`）当且仅当四件事同时成立：`new.lo <= old.lo`、`new.hi >= old.hi`、`new.quantum <= old.quantum`、`new.exact >= old.exact`。否则判收窄（`narrow`），并给出细分：

| 细分 | 触发条件 |
|---|---|
| `int_digits_drop` | decimal 的整数位（精度减标度）变少 |
| `scale_drop` | decimal 的小数位变少 |
| `range_narrow` | 取值范围变小 |
| `precision_loss` | 刻度变粗 |
| `exactness_loss` | 精确整数范围变小 |
| `length_narrow` | 字符长度上限变小 |
| `temporal_narrow` | 时间精度回退（timestamp 到 date） |

跨族（数值到字符等）判 `cross_family`；任一端不在类型格内判 `unknown`。三种都算破坏。

## 3 必填与两向结论

- `required=true → false`：`REQUIRED_LOOSENED`，读者与写者都通过。
- `required=false → true`：`REQUIRED_TIGHTENED`，写者不通过，读者通过。
- 读者向看名字能否落到同一身份、类型能否解释；写者向看类型是否容纳与是否新增约束。
- 结论三档：`COMPATIBLE`、`COMPATIBLE_BY_MAPPING`（需要建别名视图）、`BREAKING`。

## 4 时间与区间

- 存储一律 UTC，页面按 `+08:00` 显示。
- 生效区间是半开区间 `[start, end)`；`end` 为空表示不设终点。
- 重叠判定：`left.start < right.end` 且 `right.start < left.end`，缺端点按无穷远。
- 端点相邻（左区间终点等于右区间起点）不算重叠。

## 5 引用

- 下游登记给出 `sql`、`upstream`、`downstream`；SQL 里只抽 `别名.列名`。
- 解析必须过身份：先按 `(表, 列名)` 找到旧版本字段，再按 `field_id` 找新版本字段。
- 名字还在但身份换了的，判断链 `REF_BROKEN`，不允许悄悄绑到新列。
- 改名同时换类型的字段不生成别名，引用同样判断链。
- 上下游任一边缺登记即 `REF_ONE_SIDED`。

## 6 采信

- 编码回退链：`utf-8-sig` → `utf-8` → `gb18030`，先剥字节序标记再探测。
- 逻辑行按 `\n` 切分并去掉行尾 `\r`，行号从 1 开始，保留原始行号。
- 阻断行（列定义损坏、重复列、重复身份）不进判定，提示行（派生身份、未知类型、编码回退）照常参算。
- 空文件、仅表头、全空行都返回 `EMPTY_INPUT` 提示，不当作成功采信。

## 7 原因码

原因码唯一来源是 `app/reasons.py`，级别 `info / warn / break`。主原因按 `app/modules/m3_compat/priority.py` 的优先级表取，同优先级按码字典序，保证重排输入结论不变。

## 8 账目

- 旧版本字段数 = 未变 + 改名 + 换类型 + 改必填 + 冲突 + 删除
- 新版本字段数 = 未变 + 改名 + 换类型 + 改必填 + 冲突 + 新增
- 登记引用 = 可达 + 断链；可达 = 直接 + 经别名
- 列定义行 = 接受字段 + 阻断行

每个字段只进一个桶，所以四个等式成立是必要条件；差额不为 0 即判定漏项。

## 9 归档与恢复

归档包是一个 JSON 文档，格式名 `lineageguard-batch-archive`，格式版本 `1`。顶层段：

| 段 | 内容 |
|---|---|
| `batch` | 批次身份（`batch_key`、来源 `run_id`、来源版本号）、输入摘要、参数、生效区间、规则集 |
| `identity` | 内容指纹：批次键、输入摘要、规则集、参数、窗口、两版 schema 身份、快照摘要、引用摘要、结果摘要 |
| `snapshots` | `old` / `new` 必有，`base` 可选；每份带 `schema_id`、源摘要、字段清单、诊断与采信统计 |
| `refs` | 下游登记原文：`consumers` 及其 `refs`、`upstream`、`downstream` |
| `result` | 逐字段判定、影响面、引用解析结果 |
| `ledger` `mapping` `quarantine` | 账目、映射表、隔离区，恢复后页面可直接用 |
| `integrity` | `algorithm=sha256`、`payload_sha256`、逐段 `sections` 摘要、`cross_checks` 关联校验结论 |

### 9.1 摘要口径

- 摘要算在**规范化字节**上：键排序、无多余空白、UTF-8、拒绝 NaN/Infinity。
- `payload_sha256` 覆盖除 `integrity` 以外的全部内容。
- `sections` 逐段摘要，任一段被改过都能定位。
- 重排键、改空白、改缩进都不改变摘要；内容变一个字节摘要就变。

### 9.2 整包校验（先校验，后落库）

按顺序检查，任一条不过即整包拒绝（`ARCHIVE_REJECTED`，HTTP 422），一行不写：

1. 顶层对象、必需段齐全、格式名与格式版本、包类型。
2. 校验段齐全、算法只认 sha256，`payload_sha256` 复算一致。
3. 必需段的逐段摘要一致；摘要不得指向未知或不存在的段。
4. 批次段字段齐全，来源版本号为正整数。
5. 来源身份 `source_id` 合法，且与批次段 `source_run_id`/`source_version_seq` 一致。
6. 身份指纹与内容逐项一致（结果摘要、快照摘要、引用摘要都要对）。
7. `old`/`new` 快照必有且带字段清单；`base` 若在则同样必需。
8. 引用登记每项有名字与 `refs` 列表。
9. 关联完整性：声明的 `cross_checks` 全为真，且**现场复算**也全为真。复算项包括
   源摘要对输入摘要、登记引用数对声明数、账目引用数、四账是否平、字段总数、
   影响结果引用数、结果行数、结果两侧总数、破坏条数、结果逐行与结构快照是否对得上。

### 9.3 恢复口径

- **来源身份保留**：`source_id` 与来源版本号原样写回，`version_seq` 就是来源版本号，不改写。
- **本地顺序另分配**：`local_seq` 由本地序号表单调自增，与跑批共用一条线；并发恢复与并发跑批得到的本地顺序唯一。
- **本地运行号另派生**：`rs-` + 摘要，与来源 `run_id` 脱钩，避免同号顶掉。
- **本地批次键另派生**：`imp-` + 摘要；本地跑批的批次键不被占用，同输入重跑仍命中本地批次。
- **当前批次不变**：当前批次只认 `origin='local'`；导入批次进历史，不抢占当前批次、不推进本地版本号、不并入本地生效区间重叠判定。
- **判定结果原样用**：不重跑判定、不读样例目录，恢复出的 diff / 影响面 / 账目与源端逐字节一致；恢复批次再导出得到同一份字节。

### 9.4 身份与冲突

- 身份 = (`source_id`, 来源版本号)。
- 同源同号且内容指纹相同：重复导入，返回 `duplicate`，不新增行、不改已有行。
- 同源同号但内容指纹不同：隔离成冲突（`ARCHIVE_CONFLICT`，HTTP 409），写入冲突表，**不覆盖**原批次、不新增批次；同一身份只留一条冲突记录，`existing_*` 字段一旦有值不再被后来的来件清空。
- 若同源同号还有一份停在未完成导入、但内容指纹不同：同样隔离为冲突，两份都不会各自落库。

### 9.5 两阶段导入

1. `prepared`：原子占位并写入包体；此刻批次不可见（不在历史、不在当前批次、不参与任何读）。
2. `applied`：同一事务里分配/沿用本地顺序、写批次、把导入记录标成已应用；任何一步失败整笔回滚。

- 中断后只剩 `prepared`，批次**半包不可见**；可用同一归档重放，或调 `POST /api/archives/replay`，启动时也会自动续跑。
- 重放沿用已预分配的本地顺序，不跳号、不重号；重放按来源身份幂等，不会重复入库。
- 已 `applied` 的记录不会被后来的 `prepared` 覆盖。
